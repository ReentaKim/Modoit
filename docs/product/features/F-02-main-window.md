|---|---|
| 담당 | 기획 (검토: 디자인, 개발, QA) |

## 1. 왜
폴더 / 메모 목록 / 편집기의 3단 화면은 Apple 메모와 같은 익숙한 구조다. v2에서는 진짜 macOS 컨트롤(SwiftUI)로 만든다(P-3).

## 2. 요구사항
| ID | 약속 | MoSCoW | 수용 기준 | 검증 |
|---|---|---|---|---|
| FR-04 | 3단 화면 | Must | 사이드바(모든 메모, 즐겨찾기, 폴더 트리와 메모 수, 스티키 메모) / 메모 목록 / 편집기 | M1 |
| FR-25 | 사이드바 접기 | Must | 툴바 버튼, ⌥⌘S. 상태 기억 | M1 |
| FR-42 | 닫기 = 숨기기 | Must | 빨간 버튼으로 닫아도 앱과 스티키는 남는다. Dock 아이콘, ⌘0, 스티키의 "메인 창에서 열기"로 다시 보인다 | M2 |
| FR-53 | 다시 켜면 이어서 **(v2 신규)** | Must | 앱을 다시 켜면 마지막에 고른 폴더와 메모가 선택된 채 열린다. 그 메모가 없으면(지워짐·다른 앱에서 옮김) 폴더만, 폴더도 없으면 "모든 메모". 기억은 저장 폴더마다 따로 둔다(다른 저장 폴더의 선택을 가져오지 않는다) | A1, M3 |

## 3. 규칙
| # | 규칙 | 이유 |
|---|---|---|
| R-1 | 숨기기 전에 편집 중인 입력을 저장한다 | Brief 3.2-2 |
| R-2 | 창 위치·크기는 SwiftUI 기본 복원을 쓴다(v0.3은 기억하지 않았음) | 별도 구현 없이 macOS답게 |
| R-3 | 마지막 선택(FR-53)은 앱 상태(SwiftUI 장면 상태)에 기억한다. 메모 파일에는 쓰지 않는다 | 열기만 해서는 파일을 쓰지 않는다(Brief 3장). v0.3은 기억하지 않았음 |
| R-4 | 창 제목은 앱 이름이 아니라 지금 고른 사이드바 항목(모든 메모, 즐겨찾기, 폴더 이름)이다. 부제는 목록의 메모 수 (D-24) | Apple 메모와 같음. 앱 이름은 늘 보일 필요가 없다 |

## 4. 동작
- 메인 창이 숨어 있을 때 메뉴 명령의 동작은 F-11 R-1을 따른다.
