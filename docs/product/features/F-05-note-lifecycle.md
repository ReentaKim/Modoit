| 담당 | 기획 (검토: 디자인, 개발, QA) |

## 1. 왜
제목을 따로 입력하지 않는다. 첫 줄이 곧 제목이고 파일 이름이다. Finder에서 봐도 무슨 메모인지 안다.

## 2. 요구사항
| ID | 약속 | MoSCoW | 수용 기준 | 검증 |
|---|---|---|---|---|
| FR-06 | 새 메모 | Must | ⌘N 또는 작성 버튼. 지금 폴더("모든 메모"면 `메모/`)에 만들고 바로 커서 | M1 |
| FR-08 | 첫 줄 = 제목 = 파일 이름 | Must | 아래 3장 규칙 | A1, A2 |
| FR-09 | 삭제 | Must | 툴바 휴지통·우클릭 → 시스템 휴지통. 다음 메모 선택 | M1 |
| FR-10 | 빈 새 메모 정리 | Should | 이번 실행에서 앱이 만든 빈 메모만, 다른 메모로 옮길 때 휴지통으로 | A3 |

## 3. 규칙
| # | 규칙 | 예 |
|---|---|---|
| R-1 | 첫 줄의 글자(서식 기호·링크 주소 제외)가 제목 | `# 장보기` → 장보기 |
| R-2 | 파일 이름은 제목을 따른다. 저장할 때 맞춘다 | `장보기.md` |
| R-3 | 쓸 수 없는 문자(`/ \ : * ? " < > \|` 등)는 공백 | `A/B` → `A B.md` |
| R-4 | 앞뒤 공백, 끝의 점을 지운다. 너무 길면 자른 뒤 다시 지운다 | |
| R-5 | 비면 "새 메모" | |
| R-6 | 같은 이름이 있으면 ` 2`, ` 3` | `장보기 2.md` |
| R-7 | 대소문자만 바뀌면 임시 이름을 거쳐 바꾼다. 한글 NFD 이름도 같은 이름으로 본다 | |
| R-8 | HTML 엔티티로 바꾸지 않는다 | `A & B.md` |
| R-9 | 이 규칙은 `ModoitCore`에서만 계산한다 | Brief 3.1-7 |
| R-10 | 삭제한 메모에는 Brief 3.3-4를 적용한다(세션·스티키를 저장 없이 닫음) | |
| R-11 | 제목을 고친 직후 다른 메모로 가도 사용자의 선택을 되돌리지 않는다 | BUG-02 |
