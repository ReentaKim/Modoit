## 1. 범위

### 1.1 대상
- 검증 기준 코드: 앱 소스 최종 수정 2026-11-07 **19:05:33**
- 개발의 코드 고정 알림은 18:57이었습니다. 그 뒤 FR-31 개정(꺼내 둔 메모 목록)과 "보기 > 모양" 메뉴가 들어갔습니다(`NoteList.tsx`, `App.tsx`, `Sidebar.tsx`, `app.css`, `lib.rs`).
- 이 변경까지 포함해 검증합니다.

### 1.2 검증 항목
1. v0.3 신규 요구사항
   - FR-45 모양
   - FR-46 강조 색
   - FR-47 생성일
   - FR-48 토글
   - FR-49 화살표
   - FR-50 `|` 인용
   - FR-31 개정
   - NFR-14, NFR-15
2. v0.2 결함 처리 재검증
   - BUG-23~33, 36, 37(수정), BUG-38(사용자 보고)
   - BUG-34, 35는 v0.4로 미뤄짐을 확인만 합니다.
   - v0.1에서 "부분"이었던 BUG-01, 04, 10, 22의 현재 상태도 다시 판정합니다.
3. 개발이 특히 요청한 곳
   - 토글 Markdown 왕복: 중첩, 빈 내용, 다른 앱의 `<details>` 변형
   - 3-way 병합(ADR-12)이 데이터를 잃지 않는지
   - `release()`된 세션이 영원히 남지 않는지
   - 다크 모드에서 하드코딩된 색이 남았는지(`app.css`, `editor.css`, `sticky.css`)
4. v0.2까지의 회귀
   - 기존 QA 회귀 테스트(`src/qa/`)
   - Rust 하네스와 교차 검증(frontmatter 판정, 이미지 링크 재작성)을 현재 코드로 다시 실행합니다.

### 1.3 범위 밖
- BUG-34, BUG-35(PM 결정으로 v0.4)
- 실제 WebKit·AppKit 화면 동작: NSApp appearance 전환, 메뉴·대화상자 색, NSPanel의 스크립트 지연
  - 사용자가 dev 앱을 쓰고 있어 GUI 자동 조작을 하지 않습니다.
  - 10장 체크리스트로 넘깁니다(보고서 9장).

## 2. 환경
- macOS 26.6.2 (25G83), APFS(대소문자 구분 없음, 생성 시각 지원)
- Node v24.18.0, vitest 5.1.0 + jsdom 31.0.0, TypeScript ~6.0.3, rustc 1.99.1
- Tauri 2.12.5, TipTap 3.33.0, node-diff3
- 실행 중인 dev 앱, `config.json`, `scratchpad/test-vault`는 건드리지 않습니다. 파일 시스템 테스트는 새 임시 폴더에서 합니다.

## 3. 방법
v0.2 계획과 같습니다([test-plan-v0.2.md 3장](test-plan-v0.2.md)). 이번에 더한 것은 다음과 같습니다.

| 기호 | 방법 | 위치 |
|---|---|---|
| S | 시뮬레이션(회귀 테스트로 저장소에 둠) | `src/qa/v03*.test.ts(x)` 4개 추가, 가짜 백엔드에 생성 시각·`has_sticky_window`·theme/accent 반영 |
| R | Rust 하네스 | `scratchpad/qa-v03/rs`: 생성 시각(crtime) 보존 |

| C | 대비 계산 | `scratchpad/qa-v03/contrast.py`: CSS 토큰으로 WCAG 대비비 계산 |
| T | 정적 추적 | 코드 읽기 |
| M | GUI 수동 | 보고서 9장 체크리스트 |

교차 검증(X)에서 돌리는 것
- 토글 말뭉치 37개
- 병합 무작위 3,000건
- v0.2 왕복 말뭉치 120개(새 편집 가능 판정)
- frontmatter 60개
- 이미지 링크 60개

결함 테스트 표기는 v0.2와 같습니다.
- 재현된 결함은 `it.fails`로 둡니다. 고치면 실패로 바뀌므로 그때 `it`으로 바꿉니다.
