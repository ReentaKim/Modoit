# PRD — Modoit v0.3

| 항목 | 내용 |
|---|---|
| 버전 | v0.3 |
| 작성 | PM |
| 최종 수정 | 2026-11-07 |
| 상태 | 확정 |
| 이전 문서 | [PRD v0.2](PRD-v0.2.md). v0.2 요구사항은 아래에서 바뀐 항목을 빼고 그대로 유효하다 |

## 1. 배경
v0.2를 써 본 사용자 피드백(2026-11-07)
1. 꺼내 둔 메모를 여전히 넣을 수 없다 → BUG-38로 처리([PRD v0.2 9장](PRD-v0.2.md))
2. 다크 모드를 지원하자
3. 강조 색을 바꿀 수 있게 하자
4. 생성일과 수정일을 구분하자
5. `>`는 Notion처럼 접어 두기(토글)로 쓰고 싶다
6. `->`를 치면 화살표로 바뀌면 좋겠다
7. 인용은 `>` 대신 `|`로 넣자

v0.3은 **"내 취향대로 보이고, Notion처럼 빠르게 쓴다"**에 집중한다.

## 2. v0.2에서 바뀌는 요구사항

| 기존 | 변경 |
|---|---|
| 인용 단축 입력 `> ` | **`| `로 바꾼다(FR-50).** `> `는 토글(FR-48)이 된다. 파일에는 여전히 표준 인용 `> `로 저장한다 |
| 날짜 표시(목록·편집기) | 생성일과 수정일을 나눠 보여 준다(FR-47) |
| FR-31 "꺼내 둔 메모" 목록 | **지금 화면에 떠 있는 스티키만 보인다.** 다시 넣은 메모는 목록에서 사라진다. 색·위치·크기는 계속 기억하므로, 메모 목록·편집기 툴바·⌘⇧S로 다시 꺼내면 같은 자리에 뜬다. "꺼내 둔 메모에서 빼기"는 "색·위치 기억 지우기"로 이름을 바꾼다. 메모 목록의 스티키 색 점도 떠 있을 때만 표시한다 |

## 3. 신규 기능 요구사항

| ID | 이름 | 우선순위 | 설명 |
|---|---|---|---|
| FR-45 | 모양(라이트·다크) | 필수 | 설정 > 모양: **시스템 / 라이트 / 다크**. 메인 창, 스티키, 메뉴, 대화상자 모두 바로 바뀐다. 기본값은 시스템 |
| FR-46 | 강조 색 | 필수 | 설정 > 강조 색: 노랑(기본), 주황, 빨강, 분홍, 보라, 파랑, 초록, 흑연 8가지. 선택 행, 링크, 체크박스, 버튼 강조, 끌어 놓기 표시에 쓰인다. 라이트·다크 모두 읽기 좋은 색을 쓴다 |
| FR-47 | 생성일·수정일 구분 | 필수 | 편집기 위에 "만든 날 …  ·  고친 날 …"을 표시한다. 메모 목록 정렬에 "만든 날짜순"을 추가한다. 목록의 날짜는 정렬 기준에 맞춰 보여 준다. 생성일은 파일의 생성 시각이며, Modoit이 저장해도(임시 파일 교체) 바뀌지 않아야 한다 |
| FR-48 | 토글(접어 두기) | 필수 | 줄 맨 앞에서 `> `를 치면 토글 블록이 된다. 첫 줄은 제목, 그 아래는 접고 펼 수 있는 내용이다. 왼쪽 삼각형을 누르면 접히고 펼쳐진다. `/토글` 메뉴로도 만든다. 저장 형식은 `<details><summary>`(GitHub·Obsidian에서도 접어 보임) |
| FR-49 | 화살표 자동 변환 | 필수 | `->` → `→`, `<-` → `←`. 바뀐 직후 Backspace를 누르면 원래 글자로 돌아온다. 코드 안에서는 바꾸지 않는다 |
| FR-50 | 인용 `|` | 필수 | 줄 맨 앞에서 `| `를 치면 인용 블록이 된다. `/` 메뉴의 인용 표기도 `|`로 바꾼다 |

## 4. 비기능 요구사항

| ID | 내용 |
|---|---|
| NFR-14 | 토글은 FR-43(지원하지 않는 서식 보호)의 예외로 인정한다. Modoit이 쓰는 `<details>` 형식만 지원하고, 다른 HTML은 계속 읽기 전용이다 |
| NFR-15 | 다크 모드에서도 본문 글자와 배경의 명도 대비가 WCAG AA(4.5:1) 이상이다 |

## 5. 데이터 형식

```markdown
<details>
<summary>토글 제목</summary>

접혀 있는 내용

</details>
```

- 펼침·접힘 상태는 저장하지 않는다. 열 때는 항상 접힌 상태다.
- 설정(config.json)에 `theme`(`system`|`light`|`dark`)과 `accent`(색 이름)를 추가한다.

## 7. 결정 기록

| 날짜 | 결정 | 이유 | 결정자 |
|---|---|---|---|
| 2026-11-07 | `>` = 토글, `|` = 인용 | 사용자 요청. Notion과 같은 손버릇 | 사용자 |
| 2026-11-07 | 토글은 `<details>` HTML로 저장 | 표준 Markdown에 토글이 없다. `<details>`는 GitHub·Obsidian·대부분의 뷰어에서 접어 보인다. Obsidian 콜아웃(`> [!note]-`)은 다른 앱에서 인용으로 보인다 | PM |
| 2026-11-07 | 다크 모드는 창 appearance를 바꿔 구현 | 이미 있는 다크 색 토큰(prefers-color-scheme)을 그대로 쓰고, 사이드바 반투명 효과와 시스템 메뉴도 함께 바뀐다 | 개발 |
| 2026-11-07 | 강조 색은 8가지 고정 | macOS 시스템 설정과 같은 구성. 대비가 검증된 색만 쓴다 | 디자인 |
| 2026-11-07 | "꺼내 둔 메모"에는 떠 있는 스티키만 | 사용자 피드백: "안 꺼내 놨는데도 자꾸 유지하는 게 오류 같다". 넣어 둔 메모까지 보이면 지금 무엇이 떠 있는지 알 수 없다 | 사용자 |
| 2026-11-07 | v0.2 QA 재검증은 v0.3 QA와 함께 | 같은 코드를 두 번 검증하지 않는다 | PM |

## 8. v0.3 QA 결함 처리 (2026-11-07, PM 결정)
[QA 보고서 v0.3](../qa/test-report-v0.3.md)의 새 결함 8건은 모두 v0.3에서 고친다.

| 결함 | 방침 |
|---|---|
| BUG-39 병합 저장 중 입력하면 상대 줄 손실 | 저장 도중 새로 친 입력에도 상대 창 줄을 한 번 더 병합한다. 입력 중이어도 병합 결과를 화면에 다시 보여 준다(커서는 끝으로) |
| BUG-40 사라진 파일의 세션이 영원히 남음 | 저장할 때 파일이 없으면 **그 자리에 다시 만들어** 입력을 살린다(일반 편집기와 같은 동작). 앱에서 휴지통으로 보낸 메모는 세션을 먼저 버린다. 그래도 저장하지 못한 입력이 있으면 저장 폴더 변경 때 "버리고 바꾸기 / 취소"를 고르게 한다 |
| BUG-41 코드 안 `</details>`가 토글을 깸 | 토글 경계를 찾을 때 코드 블록과 인라인 코드를 건너뛴다 |
| BUG-42 대체 경로가 저장 못 한 스티키를 닫음 | 스티키가 받았다는 응답(`sticky-put-back-ack`)을 0.5초 기다린다. 응답이 없으면 창을 **닫지 않고 숨긴다**. 스티키가 깨어나면 저장한 뒤 스스로 닫고, 저장하지 못했으면 다시 나타나 거절을 알린다 |
| BUG-43 강조 색·체크 표시 대비 | `--on-accent` 토큰 도입, 일부 강조·링크 색 조정(디자인 v0.3 8장) |
| BUG-44 다크 스티키의 `/` 메뉴가 흰색 | 스티키 창에도 창 공통 토큰을 둔다 |
| BUG-45 정렬 모드에서 맨 뒤로 끌기 무반응(회귀) | "안으로 옮김"을 끌어 놓은 위치(폴더 위)로 명시해 구분한다 |
| BUG-46 불완전한 `<details>`가 편집 가능 | 짝이 맞는 Modoit 형식 토글만 지원 서식으로 인정한다. 나머지 태그는 HTML로 남겨 읽기 전용이다. 태그 안을 1~3칸 들여 쓴 문서는 들여쓰기를 떼고 읽는다 |

QA 테스트 수정 2건(개발): v03Editor BUG-46 "들여쓴 코드"는 의미 보존 기준(펜스로 정규화 허용)으로, v03App BUG-40은 선택 확인을 저장 폴더 변경 전으로 옮겼다.

**재검증에서 나온 결함 (2026-11-07)**: 둘 다 v0.3에서 고친다.

| 결함 | 방침 |
|---|---|
| BUG-47 이스케이프한 백틱 때문에 토글을 잘못 판정 | 코드 스팬은 역슬래시로 이스케이프한 백틱으로 열지 않는다. 빈 줄(문단 경계)을 넘어 짝짓지 않는다 |
| BUG-48 늦게 깨어난 스티키가 다시 꺼낸 창을 닫음 | 다시 넣기 요청에 시각(`at`)을 붙인다. 0.45초가 넘게 늦게 받은 요청은, 그사이 창이 다시 보이면(다시 꺼냄) 버린다 |
| BUG-49 0.45~0.5초 사이에 도착한 다시 넣기 요청을 무시함 | 시간으로 판단하지 않는다. 다시 꺼낼 때 메인이 `sticky-put-back-cancel`을 보내고, 스티키는 그보다 앞선 요청만 버린다 |

**v0.3 종료 (2026-11-07)**: 자동 테스트 vitest 226 + 예상 실패 2(BUG-34), cargo 45. 남은 일은 화면 직접 확인(QA 보고서 G-1, G-8, G-13, G-14, G-15, G-17)뿐이다.
