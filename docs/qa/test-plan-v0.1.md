## 1. 목적과 원칙
- PRD의 요구사항과 수용 기준을 기준으로 v0.1을 검증한다. 개발 문서(architecture.md)의 설명은 참고만 하고, 각 요구사항을 코드에서 직접 확인한다.
- QA는 앱 소스를 고치지 않는다. 결함은 재현 절차와 근거 코드 위치를 붙여 보고만 한다.
- GUI를 직접 조작할 수 없는 부분은 다음 세 가지로 보완한다.
  1. **정적 검증(코드 리뷰)**: 요구사항마다 실행 경로를 코드에서 따라가며 확인한다.
  2. **격리 시뮬레이션**: 실제 `App`/`EditorPane`/`StickyApp` 컴포넌트에 가짜 Rust 백엔드(메모리 파일 시스템)를 붙여 jsdom에서 돌린다. 경쟁 상태를 재현하는 용도다.
  3. **Rust 하네스**: `vault.rs`를 수정하지 않고 `#[path]`로 그대로 불러오는 별도 크레이트에서 엣지 케이스를 실제 파일 시스템(APFS)으로 돌린다.
- 위 방법으로 확인할 수 없는 화면, 창, OS 연동 항목은 **수동 테스트 케이스**로 남기고 사용자가 확인한다.

## 2. 범위

**포함**
- 기능 요구사항 FR-01 ~ FR-22 전부
- 비기능 요구사항 NFR-01 ~ NFR-06 (NFR-07은 문서 확인만)
- 엣지 케이스: 같은 제목, 파일 이름 금지 문자, 매우 긴 제목, 대소문자만 다른 제목, 빈 메모 이동, 입력 중 외부 수정, 삭제 직후 저장 타이머, 한글 IME, 스티키를 연 채로 파일 삭제, 저장 폴더 변경, 다중 모니터, 권한 없는 폴더, UTF-8이 아닌 파일, 다른 앱에서 만든 Markdown(표, 이미지, frontmatter)

**제외**
- PRD 비목표: 클라우드 동기화, 첨부, 표 *기능*, Windows 빌드(구조 검토만), 폴더 이름 변경·삭제, 메모 이동
- 상표 조사(NFR-07)의 사실 확인. QA는 결정 기록이 있는지만 본다.
- 성능 측정 중 앱 번들 크기(NFR-05)는 release 빌드가 없어 수동으로 남긴다.

## 5. 심각도 기준

| 심각도 | 기준 |
|---|---|
| 치명 | 앱을 쓸 수 없거나, 흔한 사용 흐름에서 데이터가 되돌릴 수 없게 사라진다 |
| 높음 | 필수 FR이 흔한 흐름에서 동작하지 않거나, 그럴듯한 조건에서 사용자 데이터가 훼손된다 |
| 보통 | FR이 특정 조건에서 어긋난다. 우회 방법이 있거나 피해가 제한적이다 |
| 낮음 | 표시, 이름 같은 사소한 어긋남, 드문 조건, 보안 강화 권고 |

확신 수준은 결함마다 따로 적는다.
- **확인됨**: 코드상 명백하거나, QA 시뮬레이션·하네스로 재현했다
- **의심**: 코드상 가능성이 높지만 실제 앱(WebKit, OS 창 관리)에서 실행해 봐야 확정할 수 있다

```bash
# 기존 테스트

cd Modoit && npx tsc --noEmit

# QA 보조 테스트 (Q = scratchpad/qa)

```

## 8. 테스트 케이스

표기: 사전조건 / 절차 / 기대 결과. 공통 사전조건은 "저장 폴더가 지정돼 있고 메인 창이 열려 있다"이다(FR-01 제외).

### FR-01 첫 실행

**TC-01 환영 화면에서 저장 폴더 선택** (M)
- 사전조건: `~/Library/Application Support/io.github.reentakim.modoit/config.json`이 없는 상태(다른 Mac 계정이나 백업 후 진행. 개발 중인 설정 파일은 건드리지 않는다)
- 절차: 앱 실행 → "저장 폴더 선택…" → 빈 폴더 선택
- 기대: 환영 화면이 나오고, 선택하면 3단 화면으로 넘어간다. config.json에 경로가 저장된다

**TC-02 설정된 저장 폴더가 사라진 경우** (S, M)
- 사전조건: 저장 폴더를 지정한 뒤 앱 종료, Finder에서 그 폴더 이름을 바꾼다
- 절차: 앱 실행
- 기대: 오류 없이 환영 화면이 나온다(`lib.rs:134-137`에서 실패를 무시하고 `get_vault`가 null을 돌려준다)

### FR-02 저장 폴더 변경

**TC-03 변경 후 재실행해도 유지** (M)
- 절차: 사이드바 아래 폴더 이름 → 다른 폴더 선택 → 앱 종료 → 재실행
- 기대: 새 폴더의 메모가 보이고 재실행 후에도 유지된다

**TC-04 스티키를 연 채로 저장 폴더 변경** (S, M)
- 사전조건: 폴더 A에서 스티키 1개를 띄워 둔다. 폴더 B에는 메모가 이미 있다
- 절차: 저장 폴더를 B로 바꾼다 → A의 스티키 창을 끌어 옮기거나 글자를 입력한다 → Finder로 B/Stickies 확인
- 기대: A의 스티키 창은 닫히거나 계속 A의 파일에 저장된다. B에 A 스티키의 복사본이 생기면 안 된다

### FR-03 기본 폴더 "메모"

**TC-05 빈 폴더 선택** (M)
- 절차: 완전히 빈 폴더를 저장 폴더로 지정
- 기대: `메모/` 하위 폴더가 생기고 사이드바에 "메모 0"이 보인다

**TC-06 거의 빈 폴더** (M)
- 절차: `.DS_Store`만 있는 폴더, PDF 파일 하나만 있는 폴더를 각각 지정
- 기대: 앞의 경우는 `메모/`가 생긴다. 뒤의 경우는 PM이 기대 동작을 정한다(현재 구현은 `.md`가 없으면 빈 폴더로 보고 `메모/`를 만든다)

### FR-04 3단 화면

**TC-07 3단 구성과 개수** (M)
- 절차: 폴더 `메모`(2개), `업무`(1개)를 준비하고 화면 확인
- 기대: 폴더 / 목록 / 편집기 3단, "모든 메모 3", "메모 2", "업무 1"

**TC-08 중첩 폴더 표시 순서** (A: QA-R4, M)
- 사전조건: 폴더 `업무`, `업무-2024`, `업무/회의`
- 기대: `회의`가 `업무` 바로 아래에 들여쓰기로 보인다

**TC-09 읽기 권한 없는 하위 폴더** (A: QA-R3)
- 사전조건: 저장 폴더 안에 `chmod 000` 폴더 하나
- 기대: 그 폴더만 빠지고 나머지 메모는 정상으로 보인다

**TC-10 숨김 폴더와 Stickies 제외** (A: UT-BE `tree_skips_stickies_and_hidden`)
- 기대: `.modoit/`, `Stickies/`는 목록·폴더에 나오지 않는다

**TC-74 UTF-8이 아닌 .md 파일** (S, M)
- 사전조건: CP949(EUC-KR)로 저장한 `옛메모.md`
- 절차: 목록에서 그 메모를 누른다
- 기대: 열리거나, 열 수 없다는 안내가 나온다. 아무 반응이 없으면 실패

### FR-05 목록 정렬과 날짜 그룹

**TC-11 날짜 그룹** (M)
- 사전조건: 터미널에서 `touch -t`로 수정 시각을 오늘, 어제, 5일 전, 20일 전, 400일 전으로 맞춘 메모 5개
- 기대: "오늘 / 어제 / 지난 7일 / 지난 30일 / 2025년" 순서. 각 행에 제목, 날짜(오늘이면 "오후 4:16" 형식), 미리보기

**TC-12 제목과 미리보기 추출** (A: UT-BE `title_preview_strip_markdown`, QA-R8, QA-T6)
- 기대: `# 장보기\n\n- [ ] 우유` → 제목 "장보기", 미리보기 "우유". 목록 제목(Rust)과 파일 이름의 제목(TS)이 같은 규칙을 따른다

### FR-06 새 메모

**TC-13 ⌘N과 작성 버튼** (M)
- 절차: "업무" 폴더 선택 → ⌘N / "모든 메모" 선택 → 작성 버튼
- 기대: 각각 `업무/새 메모.md`, `메모/새 메모.md`가 생기고 편집기에 바로 커서가 깜박인다

**TC-14 "메모" 폴더가 없는 저장 폴더에서 새 메모** (A: QA-S5)
- 사전조건: 하위 폴더가 `업무`뿐이고 "모든 메모" 선택
- 기대: PRD대로 "메모"에 생긴다(필요하면 폴더를 만든다)

**TC-15 제목 입력 직후 ⌘N** (A: QA-S2, M)
- 절차: 기존 메모의 첫 줄을 고친 뒤 0.5초 안에 ⌘N
- 기대: 새 빈 메모가 선택되고 커서가 들어간다

**TC-16 한국어 입력 소스에서 단축키** (M)
- 절차: 입력 소스를 "한국어 두벌식"으로 두고 편집기에 한글을 친 뒤 ⌘N, ⌘F, ⌘⇧N
- 기대: ABC 입력 소스일 때와 똑같이 동작한다

### FR-07 자동 저장

**TC-17 0.5초 뒤 저장** (M)
- 절차: 입력하다 멈추고 1초 뒤 외부 편집기로 파일을 연다
- 기대: 입력한 내용이 그대로 있다

**TC-18 메모 전환 시 저장** (A: QA-S1·S4의 저장 확인)
- 기대: 다른 메모로 옮기면 0.5초가 안 지났어도 남은 내용이 파일에 쓰인다

**TC-19 입력 직후 ⌘Q** (M)
- 절차: 메인 편집기와 스티키에서 각각 글자를 치고 0.2초 안에 ⌘Q → 재실행
- 기대: 마지막 글자까지 남아 있다. 빈 새 메모도 남지 않는다

**TC-20 제목 입력 직후 다른 메모 클릭** (A: QA-S1, M)
- 절차: 새 메모에 "장보기"를 치고 0.5초 안에 목록의 다른 메모 클릭
- 기대: 누른 메모가 열린다. "장보기.md"는 저장된다

**TC-21 저장 실패** (S, M)
- 절차: 메모를 연 채 Finder에서 그 폴더를 읽기 전용(`chmod 555`)으로 바꾸고 입력
- 기대: 저장 실패를 사용자에게 알리고, 권한을 되돌리면 다시 저장된다

### FR-08 제목과 파일 이름

**TC-22 첫 줄이 파일 이름** (A: UT-BE `create_and_rename_unique`)
- 기대: "장보기" → `장보기.md`

**TC-23 같은 제목 메모 두 개** (A: UT-BE)
- 기대: 두 번째는 `장보기 2.md`

**TC-24 금지 문자** (A: UT-BE, QA-T1)
- 입력: `회의: 1/2분기`, `a<b>c|d`, `???`
- 기대: `회의 1 2분기.md`, `a b c d.md`, `새 메모.md`

**TC-25 매우 긴 제목** (A: QA-T1, QA-R2)
- 입력: 한글 61자, 이모지 70개
- 기대: 60자로 잘리고 저장·재저장이 모두 성공한다

**TC-26 대소문자만 바꾼 제목** (A: QA-R1)
- 절차: `Abc.md`의 첫 줄을 "abc"로 바꾼다
- 기대: `abc.md`가 된다(번호가 붙지 않는다)

**TC-27 `&`, `<`, `>`가 들어간 제목** (A: QA-T7)
- 입력: "R&D 회의", "a < b"
- 기대: 파일 이름 `R&D 회의.md`, 목록 제목 "R&D 회의"

**TC-28 TS fileBase와 Rust sanitize_name 일치** (A: QA-T1)
- 입력: 31가지 문자열(제어 문자, 여러 종류의 공백, BOM, 길이 경계, 점으로 시작·끝)
- 기대: 두 함수의 결과가 모두 같고, 결과가 공백이나 점으로 끝나지 않는다

### FR-09 삭제

**TC-29 휴지통 버튼** (M)
- 절차: 목록 가운데 메모를 열고 휴지통 버튼
- 기대: Finder 휴지통에 들어가고 "되돌려 놓기"로 복구된다. 목록에서 바로 아래 메모가 선택된다

**TC-30 입력 직후 삭제(저장 타이머)** (A: QA-S4)
- 절차: 입력하고 0.5초 안에 휴지통 버튼
- 기대: 지운 파일이 저장 타이머 때문에 되살아나지 않는다

### FR-10 빈 새 메모

**TC-31 빈 새 메모에서 다른 메모로 이동** (A: QA-S2 관찰, 코드)
- 기대: 빈 `새 메모.md`가 휴지통으로 간다

**TC-32 외부에서 만든 빈 .md를 열었다가 이동** (A: QA-S3)
- 사전조건: Finder/터미널로 만든 빈 `외부 빈 파일.md`
- 기대: 열어 보기만 했으면 파일이 그대로 남는다(PRD는 "새 메모"만 정리 대상)

**TC-33 기존 메모의 내용을 모두 지우고 이동** (A: QA-S6)
- 기대: PM 판단 필요. PRD 문구상으로는 "새 메모"가 아니므로 남아야 한다

### FR-11 검색

**TC-34 ⌘F, 검색, Esc** (M)
- 절차: 편집기에 커서를 둔 채 ⌘F → "장보" 입력 → Esc
- 기대: 검색창으로 포커스가 옮겨지고 제목·미리보기에 "장보"가 있는 메모만 보인다. Esc로 검색어가 지워지고 전체가 다시 보인다

**TC-35 경로 검색** (M)
- 절차: "업무"로 검색
- 기대: `업무/` 폴더의 메모가 모두 나온다

### FR-12 새 폴더

**TC-36 새 폴더 Enter** (M)
- 기대: 사이드바 "+" → 이름 입력 → Enter → 폴더가 생기고 선택된다

**TC-37 새 폴더 Esc 취소** (M)
- 절차: 이름을 입력한 뒤 Esc
- 기대: 폴더가 생기지 않는다(입력창이 사라질 때 blur로 제출되지 않는지 확인)

**TC-38 특수한 폴더 이름** (A: QA-R5)
- 입력: `Stickies`, `..`, 이미 있는 이름
- 기대: 거부하거나 안내한다. 만들었다면 사이드바에 보여야 한다

### FR-13 단축 입력

**TC-39 단축 입력 전체** (A: UT-FE + QA-T2)
- 입력: `- `, `* `, `1. `, `[ ] `, `[] `, `[x] `, `# `, `## `, `### `, `> `, ```` ``` ````+공백, `---`, `—-`
- 기대: PRD FR-13 표대로 바뀐다

**TC-40 한글 IME로 단축 입력** (M)
- 절차: 한국어 입력 소스에서 줄 맨 앞에 `- `, `[ ] `를 치고 바로 한글을 이어 친다. 한글 글자를 조합하는 중에 Enter, Tab을 누른다
- 기대: 목록·체크박스로 바뀌고, 조합 중인 글자가 사라지거나 두 번 들어가지 않는다

### FR-14 Tab / Shift+Tab

**TC-41 목록·체크박스 안 Tab** (A: UT-FE)
**TC-42 목록 밖 Tab = 전각 공백 2개, 다시 읽어도 문단** (A: UT-FE)

**TC-43 글자를 선택한 채 Tab** (A: QA-T3)
- 절차: 목록 밖 문단 두 개를 드래그로 선택하고 Tab
- 기대: 선택한 글이 지워지지 않는다(들여쓰기되거나 아무 변화가 없다)

**TC-44 포커스 유지** (M)
- 절차: 목록 첫 항목, 코드 블록, 일반 문단, 제목 줄에서 각각 Tab과 Shift+Tab
- 기대: 어느 경우에도 포커스가 검색창이나 버튼으로 빠지지 않는다

**TC-75 macOS Ctrl 키 이동** (S, M)
- 절차: 편집기에서 Ctrl+N(다음 줄), Ctrl+F(한 글자 앞으로)
- 기대: macOS 기본 텍스트 이동이 동작한다(새 메모·검색이 열리지 않는다)

### FR-15 체크박스

**TC-45 체크하면 흐려지고 `- [x]` 저장** (A: QA-T4, M)
- 기대: 파일에 `- [x] 할 일`. 화면에서 글자가 `--text-3` 색으로 흐려지고 취소선은 없다

### FR-16 ~ FR-21 스티키

**TC-46 새 스티키** (M): ⌘⇧N과 사이드바 "+"로 각각 만든다 → 테두리 없는 작은 창이 뜨고 바로 입력할 수 있다

**TC-47 색 5가지** (M): 마우스를 올리면 상단 막대에 색 점 5개가 나오고, 누르면 색이 바뀌어 파일 `color:`에 저장된다

**TC-48 항상 위에 고정** (M): 핀을 켜면 다른 앱 창을 앞으로 가져와도 스티키가 위에 있다. 핀은 마우스를 치워도 보인다. 끄면 원래대로 돌아간다

**TC-49 위치·크기·색·고정 기억** (M): 옮기고 크기를 바꾸고 색과 핀을 바꾼 뒤 ⌘Q → 재실행 → 그대로 복원된다

**TC-50 다중 모니터** (M)
- 절차: 보조 모니터(배율이 다르면 더 좋다)로 스티키를 옮긴다 → ⌘Q → 보조 모니터를 분리 → 재실행
- 기대: 스티키가 보이는 화면 안에 나타난다

**TC-51 frontmatter 왕복** (A: UT-FE frontmatter 3개)

**TC-52 닫기 / 다시 열기 / 삭제** (M): 닫기(×) → 사이드바 행에 닫힘 표시 → 행을 누르면 다시 뜬다 → 행의 ×로 휴지통에 간다

**TC-53 스티키를 연 채로 Finder에서 파일 삭제** (A: QA-K2, M)
- 기대: 스티키 창이 닫히고 사이드바에서 사라진다. 파일이 다시 생기지 않는다

**TC-54 ⌘W로 스티키 닫기** (M)
- 기대: 닫기 버튼과 같게 `open: false`로 저장되어 다음 실행 때 다시 뜨지 않는다

**TC-55 실행 시 복원** (M): 스티키 2개 중 1개만 닫고 ⌘Q → 재실행 → 닫지 않은 것만 뜬다

### FR-22 외부 변경

**TC-56 쉬는 중 외부 수정** (A: QA-S7, M): 메모를 열어 두고 외부 편집기로 수정·저장 → 1초 안에 편집기와 목록에 반영된다

**TC-57 입력 중 외부 수정** (A: QA-S7): 내가 입력 중이면 내 내용이 우선한다(PRD 8장 정책)

**TC-58 외부 삭제·이름 변경** (M): 연 메모를 Finder에서 지우거나 이름을 바꾸면 편집기가 비고 목록이 갱신된다

**TC-59 스티키 입력 중 외부 수정** (A: QA-K1)

- 기대: 메인 편집기와 같은 정책. 내 입력이 사라지지 않는다

- 입력: "R&D", "a < b", 빈 줄 여러 개

**TC-61 다른 앱에서 만든 Markdown 보존** (A: QA-T5)

- 절차: 앱에서 열어 끝에 글자 하나를 입력
- 기대: 지원하지 않는 요소도 파일에서 사라지거나 바뀌지 않는다. 최소한 편집 전에 경고한다

**TC-63 휴지통 복구** (M): TC-29와 같이 확인

**TC-64 경로 탈출 차단** (A: UT-BE `rejects_escaping_paths`, `rejects_symlink_escape`, QA-R7)

- 기대: 모두 거부되거나 저장 폴더 밖에 아무것도 쓰지 않는다

**TC-65 권한 범위** (S): capabilities에 파일 시스템 플러그인이 없고, 창 범위가 `main`, `sticky-*`로 제한된다

**TC-69 메모 수백 개에서 검색 반응** (M): 500개 폴더에서 검색어를 칠 때 지연이 느껴지지 않는다

**TC-70 Windows 대비 cfg 분리** (S): macOS 전용 호출(`trash::macos`, vibrancy)이 `cfg(target_os)`로 묶여 있다

**TC-71 법적 위험** (S): PRD 결정 기록에 이름 충돌 검토와 역분석 금지 결정이 있다
