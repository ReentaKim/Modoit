## 1. 범위

### 1.1 대상
- 프런트엔드 `src/`(React 19, TipTap 3), 백엔드 `src-tauri/src/`(Tauri 2, Rust), 설정 `src-tauri/tauri.conf.json`, `capabilities/`
- 검증 시점 코드: 앱 소스 최종 수정 시각 2026-11-07 17:26:51. 그 뒤로 바뀌지 않았음을 확인하고 실행했다.

### 1.2 검증 항목
1. v0.2 신규 요구사항 FR-23~44, NFR-08~13
2. v0.1 결함 22건(BUG-01~22) 재검증. v0.1 재현 시나리오를 다시 돌린다
3. 개발 통합 중 고친 "열기만 해도 파일이 다시 쓰이는 문제"의 재검증. 아래 여섯 경우 모두에서 쓰기 경로가 없는지 본다
   - 메모 열기
   - 다른 메모로 전환
   - 체크박스 클릭(읽기 전용 포함)
   - 스티키 열기
   - 외부 변경 후 다시 읽기
   - 이미지가 든 메모 열기
4. 프런트↔Rust 계약 일치
   - 명령 이름, 인자 이름(camelCase), 결과 형태, 이벤트 내용
   - frontmatter 판정(`frontmatter.ts` ↔ `split_frontmatter`)
   - 링크 재작성(`move_entry`) ↔ 화면 경로(`paths.ts`)
   - 사이드바 순서(`sidebar.ts`) ↔ `layout.rs`
5. 경쟁 상태(`noteSession.ts`)
   - 저장 중 이동
   - 이름 변경 직후 전환
   - 스티키와 메인의 동시 편집
   - 저장 실패 중 전환

- 성능 측정(v0.1에서 500개 기준 문제없음 확인. v0.2에서 바뀐 목록 구조는 정적으로만 봄)

## 3. 방법

| 기호 | 방법 | 위치 | 비고 |
|---|---|---|---|
| A | 기존 자동 테스트 | `npx vitest run`, `npx tsc --noEmit`, `cargo test --lib` | 원문 기록 |
| S | 시뮬레이션(회귀 테스트로 저장소에 둠) | `src/qa/*.test.ts(x)` | 실제 App·EditorPane·StickyApp·ModoitEditor(TipTap)를 jsdom에서 띄운다. `@tauri-apps/api`는 `vi.mock`으로 가짜 백엔드(`src/qa/fakeBackend.ts`)에 붙인다 |
| R | Rust 하네스 | `scratchpad/qa-v02/rs` | `#[path]`로 `vault.rs`, `layout.rs`를 **수정 없이** 불러와 실제 임시 폴더에서 돌린다 |
| X | 교차 검증 | `scratchpad/qa-v02/vt`, `out/` | 같은 입력을 TS와 Rust에 넣어 결과를 비교한다 |
| T | 정적 추적 | 코드 읽기 | UI 이벤트 → 상태 → invoke → Rust → 파일까지 |
| M | GUI 수동 | 보고서 8장 체크리스트 | 사용자가 실행한다 |

시뮬레이션의 가짜 백엔드는 다음을 흉내 낸다.
- IPC 지연 2ms
- 감시기 250ms 묶음(`vault-changed`)
- `entry-moved` 이벤트
- `set_prefs` 정규화(trim)
- 쓰기·이름 맞추기 실패 주입

제목·파일 이름 규칙은 단순화했으므로 이름 규칙 자체는 R로 검증한다.

**결함 테스트 표기**: 재현된 결함은 `it.fails(...)`로 둔다. 지금은 "예상 실패"로 통과하고, 개발이 고치면 실패로 바뀐다. 그때 `it`으로 바꾸면 회귀 테스트가 된다.
