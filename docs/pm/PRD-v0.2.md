## 1. 배경
v0.1을 써 본 사용자 피드백은 다음과 같다.
1. 글자와 아이콘이 작다.
2. 폴더 구조가 평평하다.
3. 스티키와 메모가 따로 놀아서 불편하다.
4. 이미지를 넣을 수 없다.
5. 기능 아이디어가 부족하다.

v0.2는 **"메모 하나를 어디에든 꺼내 놓고, 폴더를 내 방식대로 정리한다"**에 집중한다.

## 2. v0.1에서 바뀌는 요구사항

| v0.1 ID | 변경 |
|---|---|
| FR-16 ~ FR-21 (별도 스티키) | **폐지하고 FR-30, 31, 38로 대체한다.** 스티키는 독립된 문서가 아니라 "메모를 꺼내 둔 상태"가 된다 |
| FR-12 (새 폴더) | FR-26으로 확장한다(하위 폴더, 이름 변경, 삭제) |

## 3. 신규 기능 요구사항

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| FR-23 | 글자 크기 키우기 | 필수 | 기본값이 v0.1보다 2px 크다. 본문 17, 첫 줄 26, 목록 제목 15, 목록 보조 14, 사이드바 15, 스티키 16 |
| FR-24 | 글꼴·크기 설정 | 필수 | ⌘,로 설정 창을 연다. 글꼴: 시스템 기본 / Pretendard / 명조 / 고정폭 / 직접 입력. 본문 크기 14~22px. 바로 적용되고 다시 실행해도 유지된다. 스티키에도 같은 글꼴을 쓴다 |
| FR-25 | 사이드바 접기 | 필수 | 툴바 버튼이나 ⌥⌘S로 접고 편다. 상태를 기억한다 |
| FR-26 | 폴더 계층 | 필수 | 폴더 안에 폴더를 만들 수 있다. 펼치기·접기, 이름 변경, 휴지통 삭제(안에 메모가 있으면 확인 대화상자) |
| FR-27 | 폴더 끌어 놓기 | 필수 | 폴더를 다른 폴더 **위**에 놓으면 그 안으로 실제로 이동한다. 폴더 **사이**에 놓으면 순서가 바뀐다. 자기 자신이나 하위 폴더 안으로는 넣을 수 없다 |
| FR-28 | 사이드바 정렬 | 필수 | 직접 정렬 / 이름순 / 최신순(폴더 안 메모의 최근 수정 시각). 직접 정렬 순서는 저장 폴더의 `.modoit/layout.json`에 기억한다 |
| FR-29 | 구분선 | 필수 | 폴더 우클릭 → "아래에 구분선 추가". 구분선은 끌어서 옮기고 우클릭으로 지운다. 이름순·최신순 정렬은 구분선으로 나뉜 구역 안에서만 적용되어 구역 배치가 유지된다 |
| FR-30 | 메모를 스티키로 꺼내기 | 필수 | 편집기 툴바 버튼, 목록 우클릭, ⌘⇧S. 꺼낸 스티키와 메인 편집기는 **같은 파일**을 편집한다. 한쪽에서 쓴 내용이 1초 안에 다른 쪽에 반영된다 |
| FR-31 | 스티키 다시 넣기 | 필수 | 스티키의 닫기 버튼으로 넣는다. 색·위치·크기는 기억한다. 사이드바 "꺼내 둔 메모"와 목록 행의 색 점으로 표시한다. 다시 꺼내면 같은 자리에 같은 색으로 뜬다 |
| FR-32 | 이미지 넣기 | 필수 | 붙여넣기(⌘V), Finder에서 끌어 놓기, `/이미지`(파일 선택) 세 가지 방법. 이미지는 `저장폴더/attachments/`에 복사하고, 메모에는 `![](../attachments/파일.png)` 형식의 상대 링크로 넣는다. 메모와 스티키 양쪽에 보인다 |
| FR-33 | 이미지 링크 유지 | 필수 | 메모나 폴더를 다른 폴더로 옮겨도 이미지가 계속 보인다. 앱이 상대 링크를 고친다 |
| FR-34 | `/` 명령 메뉴 | 필수 | 빈 줄이나 공백 뒤에서 `/`를 치면 메뉴가 뜬다: 텍스트, 제목 1·2·3, 점 목록, 번호 목록, 체크박스, 인용, 코드, 구분선, 이미지. `/체크`처럼 한글로 거른다. ↑↓·Enter·Esc로 다룬다 |
| FR-35 | 메모 고정 | 필수 | 목록 우클릭 → 고정·고정 해제. 고정한 메모는 목록 맨 위 "고정됨" 그룹에 나온다. 고정 여부는 파일에 저장되어 따라다닌다 |
| FR-36 | 메모를 폴더로 끌기 | 필수 | 목록의 메모를 사이드바 폴더로 끌어 놓으면 그 폴더로 이동한다. FR-33에 따라 이미지 링크도 고친다 |
| FR-37 | 아이콘 교체 | 필수 | Phosphor 아이콘(MIT). 툴바 20px, 사이드바 18px, 버튼 영역 32px |
| FR-38 | 빠른 스티키 메모 | 보통 | ⌘⇧N으로 지금 폴더에 새 메모를 만들고 바로 스티키로 띄운다 |
| FR-39 | 메모 목록 정렬 | 보통 | 수정일순(기본) / 이름순. 고정 그룹은 항상 맨 위 |
| FR-44 | 메인 창에서 다시 넣기·스티키 해제 | 필수 | (사용자 피드백으로 추가) 편집기 툴바의 꺼내기 버튼과 ⌘⇧S는 **꺼내기 ↔ 다시 넣기 토글**이다. 목록과 사이드바 "꺼내 둔 메모" 행의 우클릭 메뉴에 "다시 넣기"와 "꺼내 둔 메모에서 빼기"가 있다. 빼면 frontmatter의 `sticky`가 지워져 일반 메모로 돌아간다. 사이드바 행에 마우스를 올리면 다시 넣기·꺼내기 버튼이 보인다. 메인 창에서 넣을 때도 스티키에 입력 중이던 내용이 먼저 저장된다 |
| FR-40 | 스티키 = macOS 플로팅 패널 | 필수 | 스티키 창은 NSPanel로 띄운다. 눌러도 다른 앱의 포커스를 뺏지 않고(입력할 때만 키 입력을 받는다), 모든 데스크톱(Spaces)과 전체 화면 앱 위에 뜬다 |
| FR-41 | macOS 메뉴 막대 | 필수 | 파일(새 메모 ⌘N, 새 스티키 메모 ⌘⇧N, 스티키로 꺼내기 ⌘⇧S, 새 폴더 ⌘⌥N), 편집, 보기(사이드바 ⌥⌘S, 검색 ⌘F), 창, 도움말. 단축키는 입력 소스(한글·영문)와 상관없이 동작한다 |
| FR-42 | 메인 창 닫기 = 숨기기 | 필수 | 빨간 버튼으로 닫아도 앱과 스티키는 그대로 있다. 독 아이콘을 누르면 메인 창이 다시 나온다 |
| FR-43 | 지원하지 않는 서식 보호 | 필수 | 열 때 Markdown → 편집기 → Markdown 왕복 결과가 원본과 다르면(표 외 HTML, 각주 등) **읽기 전용**으로 열고 안내 막대를 띄운다. "그래도 편집"을 누를 때만 편집할 수 있다. 표는 지원한다 |

## 4. 신규 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-08 | v0.1에서 만든 `Stickies/*.md`는 일반 메모로 읽힌다. 이전 형식의 메타데이터(`color: …` 등)는 처음 꺼낼 때 새 형식으로 변환한다 |
| NFR-09 | 메모 파일 frontmatter는 **꺼냈거나 고정한 메모에만** 붙는다. 사용자가 직접 써 둔 다른 frontmatter 키는 지우거나 바꾸지 않는다 |
| NFR-10 | 이미지 크기 제한 20MB. 이미지 파일 이름은 겹치지 않게 만든다(날짜시각-임의값.확장자) |
| NFR-12 | **macOS 전용**. Windows 호환을 위한 분기(`cfg(windows)`, Windows 글꼴 대체 목록)는 없앤다. NFR-06(이식성)은 폐지한다 |
| NFR-13 | 저장 실패를 숨기지 않는다. 실패하면 편집기 위에 알림을 띄우고 3초마다 다시 시도한다. 앱을 끝낼 때(⌘Q) 남은 입력을 모두 저장한 뒤 종료한다 |
| NFR-11 | 사용하는 외부 자산(Phosphor 아이콘, Pretendard 글꼴)의 라이선스 고지를 앱의 "정보" 화면과 `THIRD_PARTY_NOTICES.md`에 둔다 |

## 5. 데이터 형식 (요약)

```markdown
---
pinned: true
sticky: {color: yellow, x: 1250, y: 140, w: 260, h: 260, onTop: false, open: true}
---
장보기

- [ ] 우유
![](../attachments/20261107-162233-a1b2.png)
```

`.modoit/layout.json`에는 사이드바의 직접 정렬 순서, 구분선, 정렬 방식을 둔다. 이 파일이 없어도 앱은 이름순으로 정상 동작한다.

## 6. 범위 밖 (v0.3 이후)
- 이미지 크기 조절, 쓰지 않는 이미지 정리
- 전역 단축키 빠른 메모 (이번에는 채택하지 않음)
- 본문 전체 검색, 태그, 메모 간 링크
- Windows 빌드: **하지 않는다** (2026-11-07 결정, macOS 전용)

## 8. v0.1 QA 결함 처리
v0.1 QA 보고서(`docs/qa/test-report-v0.1.md`) 결과는 결함 22건, 출시 보류 권고였다. **모두 v0.2에서 처리한다.** 처리 결과는 v0.2 QA 보고서에서 추적한다.

| 결함 | 처리 방침 |
|---|---|
| BUG-01 (높음) 외부 Markdown 훼손 | frontmatter 보존(NFR-09), 이미지(FR-32)와 표 지원, 왕복 결과가 다르면 읽기 전용(FR-43) |
| BUG-02 (높음) 메모 전환 시 선택이 되돌아감 | 편집 세션을 메모별로 분리한다. 이름이 바뀌어도 사용자가 고른 선택을 덮어쓰지 않는다 |
| BUG-03 `&` → `&amp;` | 직렬화할 때 HTML 엔티티를 쓰지 않게 고친다. 제목 추출은 Rust 한곳에서 한다 |
| BUG-04 외부 빈 파일 삭제 | 이번 실행에서 앱이 만든 새 메모만 자동 정리한다 |
| BUG-05 스티키 입력 유실 | 스티키도 입력 중(pending)에는 외부 변경으로 덮어쓰지 않는다 |
| BUG-06 선택 후 Tab이 글 삭제 | 선택 영역이 있으면 선택한 문단마다 앞에 들여쓰기를 넣는다 |
| BUG-07 읽을 수 없는 폴더 | 그 폴더만 건너뛴다 |
| BUG-08 "메모" 폴더 없음 | 없으면 만든다 |
| BUG-09 저장 폴더 변경 시 스티키 잔존 | 저장 폴더를 바꾸면 스티키 창을 모두 닫는다 |
| BUG-10 ⌘Q 직전 입력 유실 | 종료 요청을 받으면 모든 창에 저장을 요청하고, 끝난 뒤 종료한다(NFR-13) |
| BUG-11 메인 창 재열기 불가 | FR-42 |
| BUG-12 화면 밖 스티키 | 복원할 때 연결된 모니터 영역 밖이면 기본 위치로 옮긴다 |
| BUG-13, BUG-20 단축키 문제 | 메뉴 막대 단축키(FR-41)로 바꾼다. Ctrl 조합은 가로채지 않는다 |
| BUG-14 대소문자만 다른 이름 | 대소문자를 구분하지 않는 파일 시스템에서는 임시 이름을 거쳐 바꾼다 |
