# Modoit 프로젝트 문서

Modoit은 역할을 나눠 진행한다. 역할마다 문서를 남기고, 다음 단계는 앞 단계 문서를 입력으로 받는다.

## 역할과 산출물

| 역할 | 책임 | 산출물 |
|---|---|---|
| PM (기획) | 무엇을, 왜 만드는지 정한다. 범위와 우선순위를 정하고 결정을 기록한다 | [`pm/PRD-v0.1.md`](pm/PRD-v0.1.md), [`pm/PRD-v0.2.md`](pm/PRD-v0.2.md), [`pm/PRD-v0.3.md`](pm/PRD-v0.3.md) |
| 디자인 | 화면 구성, 색, 글꼴, 상호작용 규칙을 정한다 | [`design/design-spec-v0.1.md`](design/design-spec-v0.1.md), [`design/design-spec-v0.2.md`](design/design-spec-v0.2.md), [`design/design-spec-v0.3.md`](design/design-spec-v0.3.md) |
| 개발 | 구조, 데이터 형식, 인터페이스 계약, 구현, 단위 테스트를 맡는다 | [`dev/architecture.md`](dev/architecture.md), [`dev/api-v0.2.md`](dev/api-v0.2.md), [`dev/api-v0.3.md`](dev/api-v0.3.md) |
| QA (테스트) | PRD 요구사항을 기준으로 독립 검증하고 결함을 보고한다 | `qa/test-plan-v0.x.md`, `qa/test-report-v0.x.md` |
| 비즈니스·마케팅 | 공개·배포·홍보 방향을 검토하고 추천안을 낸다(결정은 대표) | [`biz/review-v0.3.md`](biz/review-v0.3.md) |

## 진행 절차 (버전마다 반복)

```
PM: PRD 작성·갱신 ──▶ 디자인: 디자인 명세 ──▶ 개발: 구현 + 아키텍처 문서 ──▶ QA: 테스트 계획 → 실행 → 결과 보고
      ▲                                                                                   │
      └────────────── 결함·개선 요청을 다음 버전 PRD 백로그에 반영 ◀────────────────────────┘
```

- 요구사항 ID는 PRD에서 붙인다(`FR-xx` 기능, `NFR-xx` 비기능). 디자인, 개발, QA 문서는 모두 이 ID로 서로를 가리킨다.
- 결정 사항은 PRD의 "결정 기록" 표에 남긴다. 누가, 언제, 무엇을, 왜 정했는지 적는다.
- QA는 개발과 독립적으로 PRD와 코드를 보고 검증한다. 개발 쪽 주장을 그대로 믿지 않는다.
