# 2차 스파이크 — 꾸밈이 있는 네이티브 스티키 편집기

[v2 아키텍처](../../docs/dev/architecture-v2.md) 3.3(V2-10)을 확인하려고 만든 시험판이다(V2-11). 제품 코드가 아니다.
줄 해석과 편집 규칙은 제품 코드인 `macos/Sources/ModoitCore/StickyMarkup.swift`에 있고, 여기에는 그것을 `NSTextView`에 붙이는 부분만 있다.

```bash
cd spike/sticky-editor
swift build
BIN=$(swift build --show-bin-path)/StickyEditorSpike
$BIN --selftest                         # 입력을 재현해 검사 (종료 코드 0 = 통과)
$BIN <메모.md> [<메모.md> …]             # 스티키로 띄운다. 0.5초 뒤 자동 저장
$BIN --snapshot out.png <메모.md>        # 화면을 그림으로 저장
```

## 방식
- `NSTextView`(TextKit 1)의 내용 = Markdown 원문. 글자를 바꾸지 않고 속성만 입힌다.
- 숨길 기호(`- [ ] `, `# `, `**`, `](주소)`)는 0.01pt 투명 글꼴로 만들어 폭을 없앤다.
- 점, 번호, 체크박스, 인용 막대, 구분선은 레이아웃 매니저가 여백에 그린다.
- 체크박스를 누르면 원문의 `[ ]` ↔ `[x]` 한 글자만 바꾼다.

## 결과 (2026-11-10, MacBook Pro M5 Pro)

| 확인한 것 | 결과 |
|---|---|
| 제목 1~3, 점·번호 목록, 체크박스(중첩), 굵게·기울임·취소선·인라인 코드·링크, 인용, 구분선이 꾸며져 보인다 | 됨 (`--snapshot`으로 확인) |
| Enter가 목록·체크박스·인용을 잇고, 빈 항목에서 목록이 끝난다. Tab·Shift-Tab 들여쓰기. 단축 입력 `[] ` → `- [ ] ` | 됨 (자체 검사) |
| 체크는 한 글자만 바꾼다. 저장하면 frontmatter와 고치지 않은 줄은 바이트 그대로다 (NFR-21, F-08 R-9) | 됨 (자체 검사) |
| 한글 조합(재현): 조합 중 꾸밈·저장을 건드리지 않고 글자가 남는다 | 됨 (자체 검사. **실제 입력기는 수동 확인 SP-03**) |
| 조합 중 다른 쪽에서 다른 줄이 바뀜 → 조합이 끝난 뒤 3-way 병합, 양쪽 입력이 남고 커서가 제자리 | 됨 (자체 검사) |
| 메모리 (release, phys_footprint, 메인 창 없음) | 스티키 1개 18 MB, 5개 26 MB, 10개 37~38 MB → **1개당 약 2.2 MB** |

1차 스파이크(꾸밈 없는 원문)의 "1개당 약 5 MB"보다 나쁘지 않다. 목표(NFR-17: 1개당 20 MB 이하)를 크게 밑돈다.

## 알게 된 것 (제품 구현에 반영)
1. **편집 처리 도중에 속성을 바꾸면 안 된다.** `willProcessEditing`에서 꾸미면 NSTextView가 커서를 문단 끝으로 옮긴다. 편집이 끝난 뒤(`didChangeText`) 꾸민다.
2. **조합 중에 본문을 바꾸면 조합이 끊긴다.** 빈 변경이어도 그렇다. 다른 쪽의 변경은 조합이 끝날 때까지 미뤘다가 병합한다(F-07 R-4를 구조로 지킨다).
3. **판정에서 역슬래시가 있으면 TipTap으로 보낸다.** TipTap은 `*`, `_`, `[` 앞에 `\`를 붙여 저장하므로, 그런 글자가 든 메모는 네이티브로 열리지 않는다. 가설 H-2(TipTap 비율 20% 이하)에 영향을 줄 수 있다. 네이티브에서 `\`를 숨기는 것은 어렵지 않으니 M7에서 넣는다.

## 남은 일 (M7)
- 화살표 키가 숨긴 기호를 한 글자씩 지나간다(커서가 잠깐 멈춘 듯 보인다). 숨긴 범위를 건너뛰게 한다.
- 여러 줄 목록 항목, 줄 안 줄바꿈은 지금 TipTap으로 보낸다.
- `/` 메뉴, 링크 열기(백로그 B-10), 다크 모드 색, 스티키 색 5가지.
- 0.01pt 글꼴 대신 글리프를 아예 만들지 않는 방법(`NSLayoutManagerDelegate`)과 비교.
